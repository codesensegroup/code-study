## 學習目標

> 把 Claude Code 從「聊天機器人」升級為「能自主完成任務的 AI 工程師」：掌握 context 管理、CLAUDE.md 專案知識沉澱、Plan→Review→Execute 工作流，以及小步驟驗證、Agent 思維、平行工作等實戰技巧。

## 核心訊息

這篇官方最佳實踐其實只在強調一件事：

> **不要把 Claude Code 當聊天機器人，而是把它當成「可以自主工作的 AI 工程師」。**

Claude Code 的強項不是回答問題，而是：

- 讀整個 codebase
- 自己探索架構
- 執行 terminal 指令
- 修改多個檔案
- 跑測試
- 自主完成任務

但要發揮效果，關鍵在於 **上下文管理（context management）** 與 **工作流程設計**。

## 12 個重點速覽

1. **Context window 很珍貴** — 越接近滿載、塞越多無關噪音越容易失準，要主動用 `/clear`、`/compact` 管理
2. **「證據」比 AI 自信重要** — 官方標註為「the single highest-leverage thing」：要求看 test output、build log、screenshot
3. **`CLAUDE.md` 是核心武器** — 把專案知識永久灌進 AI，每次自動載入
4. **先規劃，再動手** — Plan → Review → Execute（官方 4 階段：Explore → Plan → Implement → Commit）
5. **小步驟 + 持續測試** — TDD、頻繁 commit、立即 lint，避免 hidden regression
6. **把 Claude 當資深工程師問** — onboarding 與 codebase 探索的最佳用法，直接拋問題
7. **要把它當 Agent，不是 Copilot** — 描述目標，讓它自己想辦法完成
8. **Parallel sessions 很強** — worktree / 多 terminal 分工，效率倍增
9. **配置你的環境** — CLAUDE.md / Permissions / CLI tools / MCP / Hooks / Skills / Subagents / Plugins，一次設好終身受惠
10. **寫出精準 Prompt** — 劃範圍、指來源、引 pattern、描述症狀；用 `@file`、貼圖、URL、pipe 餵資料
11. **避開五大失敗模式** — Kitchen Sink / Over-correct / Over-spec CLAUDE.md / Trust-then-verify gap / Infinite Exploration
12. **其他官方技巧** — Session 控制（`/rewind` / `--continue` / `--resume`）、Interview 模式、`claude -p`、Subagent 兩種用法、Permission modes

## 建議閱讀順序

1. 先建立基本功：第 1、2 點（context 管理 + 要求證據，這是官方最強調的兩件事）
2. 再建立心態：第 7 點（Agent 思維）
3. 配置環境：第 3、9 點（CLAUDE.md + 完整環境配置）
4. 套用工作流：第 4、5 點（Plan→Execute、小步驟）
5. 進階使用：第 6、8 點（codebase 探索、平行工作）

## 總結

> 「如何把 Claude Code 從聊天 AI，變成真正能協作開發的大型 agent 系統。」

核心能力：

1. Context management
2. Persistent project knowledge（`CLAUDE.md`）
3. Planning before coding
4. Incremental verified changes
5. Agent workflow instead of autocomplete mindset

## 🧭 最後提醒：規則是起點，不是終點

官方文件最後一節「Develop Your Intuition」提醒：上面所有準則都是**一般情況下管用的預設模式**，經驗累積後你會學會何時該打破：

- 深陷同一個複雜問題時，**讓 context 累積**反而對
- 探索性任務，**跳過 plan 直接試**反而快
- 想看 AI 怎麼詮釋問題時，**模糊 prompt** 反而能挖到沒想過的角度

直覺要靠累積：Claude 答得好就觀察你做對了什麼；卡住就問自己為什麼 — 這份判斷力沒有任何指南寫得出來。
