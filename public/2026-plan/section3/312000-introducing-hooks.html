Hooks 攔截與自動化機制

你不必總是讓 AI 自主決定一切。透過設定 Hooks，你可以在 Claude 執行工具的「事前 (Pre)」強制踩煞車，或在「事後 (Post)」觸發程式碼檢查並回傳修正建議。

3. Hook 的註冊位置 (設定檔層級)

除了在對話框輸入 /hooks 指令，你也可以手動編輯設定檔。Claude 支援三種層級的配置檔。

設定檔目錄 (Config Files)
  • ~/.claude/settings.json
  • .claude/settings.json
  • .claude/settings.local.json
Global (全域)

影響你電腦上的所有專案

放在 User 的 Home 目錄下。適合設定你個人的防護習慣，例如：「永遠禁止讀取任何名為 .env 的檔案」。這對你機器上執行的所有 Claude Code 專案都有效。

Project (專案共用)

團隊共享的規範

放在專案資料夾內，應該被 Commit 到 Git 中。適合設定團隊共同的規範，例如：「只要編輯過 JS 檔，就統一執行專案裡的 npm run format」。這樣團隊中任何使用 Claude Code 的人，都會遵守這個規範。

Local (本機不提交)

專屬你的個人覆寫

放在專案資料夾內，但必須加入 .gitignore 中不提交。適合你在本地端開發時，想加上一些只對你個人有用的 Hook 測試或暫時性的除錯指令。
