重點 #7 · 進階

Parallel Sessions

不要一個 Claude 排隊做所有事 — 開三個 terminal，三件事同時跑。

Terminal A · Backend

$ claude

→ 重構 /api/users 路由

→ 拆出 service 層

→ 加錯誤處理

✓ done. running tests...

Terminal B · Frontend

$ claude

→ 把 UserList 改成 virtualized

→ 加 skeleton loading

→ 套用新的 design tokens

✓ build success

Terminal C · Tests

$ claude

→ 補 auth module 測試

→ coverage 從 62% 提到 89%

→ 寫 edge case

✓ 14 new tests pass

三件事同步進行 · 時間直接 ÷ 3

注意事項

🌿

不同 branch / worktree

避免兩個 Claude 同時改同一檔案打架。

🎯

任務要正交

backend / frontend / tests，彼此不踩腳。

📋

最後人工 review

三邊結果整合時還是要看一眼。

🔀

萬一三個 session 必須動到同一份檔案？

純粹「任務正交」很難 100% 做到（router、types、config 常被多方共用）。下面是實戰防呆四招。

① git worktree 物理隔離

每個 session 開獨立目錄 + 分支，本機檔案系統就分開了。

$ git worktree add ../shop-api feat/api

$ git worktree add ../shop-ui feat/ui

# 三個 Claude 各在自己目錄

② Prompt 明確劃界線

在 prompt 跟 CLAUDE.md 都寫死可動 / 不可動範圍。

✓ 你只能改 src/api/

✗ 不要碰 shared/types.ts

⚠ 需要新 type 時先停下來問

③ 共享檔案凍結 + 整合 session

把 types、config、router 列為「共享凍結區」，三邊都不改；最後開一個整合 session 統一處理。

# shared/ ← 凍結

session A · B · C 各自完成

→ 開 session D 統一更新 shared/

④ 小步 commit + 頻繁 rebase

每個 session 做完一段就 commit；其他 session 開新任務前先 git pull --rebase，衝突早發現。

commit 小 → 衝突好解

commit 大 → merge 地獄

💡 核心原則：「能物理隔離就物理隔離，不能就劃界線，最後一定要有人整合」
