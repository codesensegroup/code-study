工具鏈 > Prompt

Claude Code 的威力不是 prompt engineering，而是周邊工具的組合。

💬 prompt 基礎
🐚 shell tools bash / find / grep
🌿 git commit / branch / diff
🧪 test runner vitest / jest / pytest
🧹 linter eslint / ruff
📜 CLAUDE.md 專案知識
🪝 hooks + permissions 自動化攔截
🤖

= 真正的 Agent

tools × discipline

兩種派系

❌ Prompt 派

「我有超強 prompt」

  • • 把 prompt 寫成五頁長
  • • 一直微調咒語
  • • 結果還是不會跑測試
  • • 還是要自己 git commit

✅ 工具鏈派

「我有完整 workflow」

  • • CLAUDE.md 寫好規則
  • • Hook 自動 lint + test
  • • Permissions 限制危險指令
  • • Prompt 反而可以很短

🎬 情境範例

任務：在電商加「使用者追蹤功能」（新 API + UI + 測試 + 部署）

❌ Prompt 派

把一切塞進巨型 prompt

$ 加 follow 功能，要：

- 用 TypeScript，禁止 any

- 命名要 camelCase

- 寫完跑 npm test

- 用 conventional commit

- 不要動 src/legacy

- 不要碰 .env

- 加完要 lint

- 加 unit test 跟 e2e test

- PR 不要超過 300 行

... (再 50 條)

⚠️ AI 寫到後面忘記前面規則

⚠️ 你下次又要重貼一次

⚠️ 新人加入要學「咒語」

✅ 工具鏈派

短 prompt + 環境自動補位

$ 加 follow 功能

# 就這樣，10 個字

背後環境自動處理：

📜 CLAUDE.md → coding style / commit / 禁忌

🪝 PreToolUse hook → 阻擋 .env / legacy

🪝 PostToolUse hook → 自動跑 lint + test

🛡️ permissions → 危險指令需確認

⚙️ husky → commit 訊息格式自動檢查

✓ 寫完自動 lint + test，錯了它自己 retry

✓ 規則永久在環境裡，新人 clone 就有

# 一句話心法

不要練咒語，去搭環境 — 工具鏈才是真正的乘數
