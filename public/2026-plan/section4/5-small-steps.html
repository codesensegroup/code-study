重點 #5 · 紀律

小步驟 + 持續測試

頻繁 commit、立即 lint，不要讓 AI 一次改整個專案。

✅ 好 小步快跑
✓ pass
✓ pass
✓ pass
✓ pass

→ rollback 容易 / 找 bug 快 / 沒有 hidden regression

❌ 不好 一口氣大改
💣
✗ 47 tests failed, 不知從何下手

→ rollback 痛 / 不知哪行壞 / hidden bug 滿地

三個紀律

🧪

TDD

先寫測試，再讓 Claude 改，目標明確不亂飄。

🧹

Lint immediately

改完馬上 lint，不要累積一堆風格問題。

🏃

Run tests often

每個小段落跑一次，hidden regression 立刻浮出來。

📝 範例：同樣五個需求，兩種問法

需求：幫一個部落格加上「文章按讚 + 留言 + 通知 + 報表 + 後台」

❌ 一次到位

「全部幫我做完」

$ 幫我加：

1. 文章按讚功能

2. 留言系統

3. Email 通知

4. 後台統計報表

5. Admin 管理介面

→ 改了 23 個檔案

→ test 全紅，不知道哪個壞

→ 第 3 點通知功能耦合到留言系統

→ 想 rollback「留言」結果牽動「按讚」

→ 💣 整個 PR 報廢

✅ 階段問法

「一次一個，跑完測試再下一個」

$ 1. 先做按讚功能（含 test）

✓ pass · commit

$ 2. 加留言系統

✓ pass · commit

$ 3. 接 Email 通知

✓ pass · commit

$ 4. 後台報表

✓ pass · commit

$ 5. Admin 介面

✓ pass · commit

→ 每步都有獨立 commit

→ 出錯只 rollback 那一個

→ 第 3 步意外影響第 2 步立刻發現

→ PR 切成 5 個，review 也輕鬆

AI 寫 code 很快，但「驗證」比寫得快更重要
