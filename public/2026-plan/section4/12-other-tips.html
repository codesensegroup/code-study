其他官方技巧

官方文件提到、但篇幅較小的 5 個進階技巧 — 條列式速覽。

⏪

① 即時修正 Course-Correct

Claude 偏掉的瞬間就要拉回來，越早越好。會議室裡 5 個快捷鍵：

Esc 中斷它的動作，context 保留可繼續對話
Esc Esc 開啟 rewind 選單，回到任意 checkpoint
/rewind 同上，用指令打開
Undo that 直接叫它把剛才的改動倒回去
/btw 問個不想留在 context 的小問題（答案顯示後不會加入對話歷史）

💡 同一個錯誤糾正兩次後 → /clear + 寫更精準的新 prompt，比繼續糾正快

🎤

② 讓 Claude 反問你 — Interview Mode

大型功能要做但你還沒想清楚 → 不要硬寫 prompt，叫它用 AskUserQuestion 訪談你。

$ I want to build [brief description].

Interview me in detail using AskUserQuestion.

Don't ask obvious questions, dig into the hard parts.

Keep going until covered everything, then write SPEC.md.

→ 它會挖出你沒想過的 edge case、UI/UX 取捨、技術選擇。寫完 spec 後另開 fresh session 實作。

🤖

③ Non-Interactive Mode — 接 CI / pipeline

用 claude -p "prompt" 讓 Claude 不開 session 直接跑，可串進 CI、pre-commit hook、批次腳本。

# 單次查詢

claude -p "Explain what this project does"

# 結構化輸出給腳本用

claude -p "List all API endpoints" --output-format json

# Streaming 即時處理

claude -p "Analyze log" --output-format stream-json --verbose

→ 配 --allowedTools 限制權限，無人值守時更安全。

⚖️

④ Adversarial Review — 用 fresh subagent 找碴

Claude 跑很久之後，找一個沒看過實作過程的 subagent 來 review diff。看到的只有結果跟標準，不會被「我剛剛這樣寫」帶偏。

$ Use a subagent to review the rate limiter diff against PLAN.md.

Report gaps that affect correctness or stated requirements.

# 或直接用內建 /code-review skill

⚠️ Reviewer 被指派找碴就一定會找出東西。要它只報關鍵問題，不然會 over-engineer。

🛡️

⑤ Permission Modes — Shift+Tab 切四檔

每個動作都按確認太煩、全自動又不安全 — 官方提供四個主要模式，按 Shift+Tab 循環切換：

Ask before edits (default)

每個動作都問你 — 預設行為，敏感工作用。

Edit automatically (acceptEdits)

檔案編輯自動過，但 shell 命令仍問你 — 邊改邊在編輯器看 diff。

Plan mode (plan)

只讀檔、跑探索性指令、寫計畫 — 不會動到任何 source。

Auto mode (auto)

全自動執行 + 背景 classifier 自動擋風險動作。需 Sonnet 4.6 / Opus 4.6+。

⚙️ 另外兩個進階模式（不在 Shift+Tab 循環）：

dontAsk — CI 用，只跑白名單，其餘全擋
bypassPermissions — 跳過全部檢查，容器/VM 內才用

💡 另外還有兩個獨立工具疊在 mode 之上：/permissions 設細粒度規則（allowlist/deny）、/sandbox 做 OS 級隔離。

# 一句話心法

這 5 招都是「降低摩擦」— 知道何時用，比每招都精通更重要
