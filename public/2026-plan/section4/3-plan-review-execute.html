重點 #3 · 工作流

Plan → Review → Execute

不要說「幫我直接改」。讓 AI 先想、給你看、確認了再動手。

1

PLAN

提出策略與步驟

2

REVIEW

你決定改不改、怎麼改

3

EXECUTE

按計畫實作

# Plan

→ 分析 auth.ts 結構 ✓

→ 列出三個修改點，等待確認 ✓

# Review

→ 你說：「第二點先跳過」 ✓

# Execute

→ 套用變更，跑測試 ✓

→ Done.

反模式 vs 正確做法

❌ 反模式

「幫我直接改」

$ 修一下 login bug

⚠️ 改了 6 個檔案，砍了一個 helper，新增了你沒同意的 lib

⚠️ 你不知道改了什麼，rollback 也痛

⚠️ 複雜引用（如 WordPress 本體 + 外掛互相 hook）動一處

→ 連環炸 N 個外掛，連 AI 自己都不知道波及範圍

✅ 正確

「先給我計畫」

$ 看一下 login bug，給我 plan

🔍 先調查：grep 引用、列出相關檔案與外掛

📝 預計要修改：auth.php : 3 處 · plugin-x hook : 1 處

→ 列三個可能原因 + 對應改動

→ 你選擇方案 B，再按 plan 執行

💡 實戰小技巧

直接按 Shift+Tab 切換到 Plan Mode — Claude 只規劃不動手。
