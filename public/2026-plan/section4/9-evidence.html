重點 #9 · 驗證

證據 > AI 自信

"This should work" 是最危險的一句話。要看實際輸出，不要相信表情。

🤖

Claude says:

✨ "This should work. I've updated the auth logic and it should now handle all edge cases."

注意：「should」「should be」「I believe」都是警訊詞

$ npm test

✗ FAIL auth.test.ts

● should reject expired token

expected: 401

received: 200

Tests: 3 failed, 18 passed

→ 證據打臉「should work」

該要求看的證據

🏗️

Build output

真的編過嗎？

🧪

Test output

幾條 pass / fail？

📸

Screenshot

畫面真的對嗎？

📜

Actual logs

真的有跑到嗎？

⚠️ AI 警訊詞

看到這些字 → 你要主動要求看「真的證據」：

"should work"
"I believe"
"probably"
"in theory"
"this is the fix"
"看起來沒問題"

🎬 情境範例

任務：修 login bug — 密碼含特殊字元（!#$）的使用者登入失敗

❌ 相信 AI 表情

「看起來沒問題就 merge」

🤖 我改好了 regex，should work now

🤖 邏輯看起來正確，邊界 case 也處理了

$ git merge ✓

$ deploy to prod ✓

⏰ 隔天早上 9:00

📞 客服：50 位用戶反映登入失敗

📊 監控：login error rate 從 0.2% → 17%

💣 regex 是改了，但 !#$ 還是被擋

原來 AI 從來沒實際跑過那條測試

✅ 要求證據

「跑給我看」

$ 改完，把 auth.test.ts 跑起來貼完整輸出

→ Tests: 2 failed, 18 passed

✗ should accept password with !#$

✗ should accept password with spaces

$ 修這兩個 case，再跑一次

→ Tests: 20 passed ✓

⏰ merge 前發現問題

📸 還要求：實際用 test!#$user 登入截圖

📜 staging log 看 auth flow 確實 200 OK

✓ 確認 3 種證據後才 merge

隔天客服 0 通電話

💬 改變問法

❌ 不要問

"修好了嗎？"

✅ 改成問

"跑 test，貼完整 output 給我看"

# 一句話心法

不要相信 AI 的表情 — 要看 test output、build log、screenshot
